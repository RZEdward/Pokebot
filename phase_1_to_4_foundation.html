Project Hitmonlee · Phase 1 foundation

Steps 1–4 are now a runnable learning base.

A small planar biped can be simulated, trained with PPO, evaluated on held-out initial conditions, watched through a local live monitor, and replayed as video. Camera and command paths are present as inspectable prototypes. The numbers below describe this deliberately provisional model; they do not establish a physical digital twin or sim-to-real transfer.

Train while viewing

Start the simulator with the native viewer, then run the browser monitor against that run directory in a second terminal. The viewer is the MuJoCo scene; the local browser page plots the latest simulated pose and reward trend.

.\.venv\Scripts\python.exe -m hitmonlee_sim.train --steps 50000 --live --run-dir runs\balance-live .\.venv\Scripts\python.exe -m hitmonlee_sim.dashboard --run-dir runs\balance-live

Speak a command locally

.\.venv\Scripts\python.exe -m pip install -e ".[speech]" .\.venv\Scripts\python.exe -m hitmonlee_sim.voice --download-model .\.venv\Scripts\python.exe -m hitmonlee_sim.voice --listen

The offline grammar routed synthesized “stand” to `balance`; rejected “walk forward” and negated “don't stop”; and mapped “stop” to a supervisor request. These clips prove the audio-to-intent path, not human-speaker accuracy. Voice architecture notes. Stop is never a physical e-stop signal.

What is intentionally left for your learning phase

  • Trace observation fields, reward terms and joint-position actions in `env.py`; see how PPO and the held-out evaluator are wired in `train.py` and `evaluate.py`.
  • Replace provisional masses and gains only with evidence from CAD, component specifications and measured actuator traces.
  • Introduce modular task terms when a second task justifies them, following mjlab and Isaac Lab patterns. Keep the one-task base easy to follow.
  • Do a fair backend bake-off on the same MJCF, action semantics, seeds, and contact/actuator trace before choosing a GPU stack.
  • Add microphone capture/ASR, a trained visual detector, and walking only as separately testable modules with explicit uncertainty and safety gates.
